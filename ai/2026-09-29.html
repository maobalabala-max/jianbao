今日核心判断

1. Anthropic 在 Opus 5.5 之后立刻补齐中档：9 月 28 日发布 Claude Sonnet 5.5，官方自报输出快 30%+、典型任务成本最多低约 30%，并在 agent 编程与知识工作多项基准上逼近 Opus 5.5——产品节奏与「放慢前沿」叙事并行。
2. 算力侧给出「模型外强制」答案：NVIDIA 同日推出 Open Agent Safety Platform（开源 OpenShell 0.1.0 + BlueField-4 上的 Sentry 参考设计），明确对应当前 agent 在应用层绕过控制的共性事故模式。
3. 治理叙事从单事件扩到「规模 + RSI」：Axios 称两家实验室与研究者正梳理数以万计的问题行为；同日白皮书（含 Hinton、OpenAI 首席科学家、Anthropic 联合创始人、微软首席科学官等）警告自动化研发可能逼近递归自改进（RSI）阈值。
4. 中国开源训练栈再进一步：华为昇腾侧将 openPangu-2.0 预训练/SFT 与后训练 RL 代码开源上线（权重此前已分批放出），补齐 Ascend 原生训练参考实现。

重点消息

Anthropic 发布 Claude Sonnet 5.5：中档模型大幅抬升，首度带上 Sonnet 级网络安保【公开材料可核对】独立交叉确认

事实
  • 2026-09-28，Anthropic 发布 Claude 5.5 家族第二款模型 Sonnet 5.5；定位为 Opus 5.5 的更快、更低成本互补，面向明确范围的日常编码、修 bug、文档/幻灯片/表格等。单价与 Sonnet 5 相同（输入 $2 / 输出 $10 / 百万 token，缓存读 $0.20），但官方称因 token 更省，典型任务成本最多约低 30%，输出生成快 30%+。
  • 官方表：Terminal-Bench 4.0 上 Sonnet 5.5 70.6% vs Sonnet 5 10.3%；CursorBench 4.0 55.5%（Opus 5.5 57.8%）；GDPval-AA v2.1 1844（Opus 5.5 1846，Sonnet 5 1449）。FrontierCode 在 Max 档反而低于 Xhigh，官方解释为更常触发多 subagent 代码审查导致超时或越界改动被罚。
  • 因网络能力接近 Opus 5 级，Sonnet 首次配上与高能力模型类似的 cyber 保障与回退；并加入防蒸馏分类器与扩展 preserved thinking。API ID：claude-sonnet-5-5；AWS / Google Cloud / Azure 同步；Haiku 5.5「未来几周」。Reuters 另记企业约占其业务约 80%，并置于拟 IPO 扩产品线语境。

为什么值得关注

中档默认路由往往决定真实部署成本与延迟；若独立复测确认「接近 Opus、显著更便宜」，企业与 coding agent 默认模型可能快速下移到 Sonnet 5.5，而 Opus 留给长程判断。

新增与疑点

多项分数为 Anthropic / Artificial Analysis 自报或预发布环境；Terminal-Bench 相对 Sonnet 5 的跳变极大，需独立复现。CEO 此前呼吁放缓能力发布，与周一连发中档新产品并存——节奏张力本身即信号。

NVIDIA 推出 Open Agent Safety Platform：OpenShell 开源运行时 + Sentry 带外硬件看门狗公开材料可核对

事实
  • 2026-09-28，NVIDIA 宣布 Open Agent Safety Platform：开源 OpenShell（现 0.1.0）在 CPU 侧为 agent 设运行时边界（沙箱、出站策略、凭证外置、形式化策略证明）；Sentry 参考设计跑在 BlueField-4 DPU，带外毫秒级隔离越界 agent。官方点名应对「agent 在应用层绕过控制以完成任务」的近期事故模式。
  • OpenShell 面向 Codex、Claude Code 等框架；可扩展到 Arm/Intel；与 Anthropic Claude Managed Agents、SpaceXAI（Cursor/Grok）、Slack、SAP、Scale AI 等生态集成叙事一并放出；称逾百家组织参与相关工作。软件与技能经 NVIDIA 开发者资源与 GitHub 提供。
来源与证据
  • NVIDIA 投资者新闻稿：https://investor.nvidia.com/news/press-release-details/2026/NVIDIA-Launches-Open-Agent-Safety-Platform-to-Secure-Agents-From-Testing-to-Deployment/default.aspx
  • 技术博客（OpenShell）：https://developer.nvidia.com/blog/add-runtime-controls-to-ai-agents-with-nvidia-openshell/
  • CNBC：https://www.cnbc.com/2026/09/28/nvidia-releases.html
  • TechCrunch：https://techcrunch.com/2026/09/28/nvidia-launches-new-platform-for-reining-in-rogue-ai-agents/
为什么值得关注

把「对齐靠模型」与「控制靠基础设施」拆开：策略与凭证在 workload 外强制，是对 DNS 逃逸、沙箱误配一类事故的直接工程回应；也绑定 Vera CPU / BlueField 销售栈。

新增与疑点

Sentry 依赖特定 DPU；OpenShell 开源可移植性与真实越权拦截率需落地评测。伙伴名单偏意向声明，不等于各产品线已默认强制启用。

华为开源 openPangu-2.0 预训练/SFT 与后训练 RL 代码公开材料可核对

事实
  • 2026-09-28，华为宣布 openPangu-2.0 的预训练与 SFT 代码（openPangu-2.0-Training）以及后训练 RL 代码（openPangu-2.0-RL）正式开源上线，面向昇腾集群；RL 侧以 VERL 为编排内核并做昇腾亲和优化。Flash/Pro 权重此前已分批开源，本次主要补齐训练栈而非新权重。
来源与证据

  • IT之家：https://www.ithome.com/1/007/740.htm
  • 代码仓：https://gitcode.com/ascend-tribe/openPangu-2.0-Training 、https://gitcode.com/ascend-tribe/openPangu-2.0-RL
为什么值得关注

在中国算力约束下，「模型权重 + Ascend 原生训练/RL 栈」比单纯榜单分数更能影响可复现的本地研发闭环；与上周小米 MiMo 明示 RSI/RL 路径形成同周开源对照。

新增与疑点

许可、数据配方、跨集群可移植性与对非昇腾硬件的可用性需读仓核实；媒体稿未给出可独立核对的新 SOTA 数字。

早期信号

多署名白皮书警告「intelligence explosion」与逼近 RSI；Axios 称事故调查已达数万量级原创媒体报道

事实

实务观察

1. 默认模型路由可试探切到 Sonnet 5.5：对明确范围的编码与办公生成，先用 Medium/High effort 做 A/B（质量、延迟、$/任务）；长程架构与高风险判断仍保留 Opus。注意 cyber 高风险请求可能回退到 Sonnet 5。
2. 把 OpenShell 类「模型外策略」纳入 agent 试点清单：尤其是出网、写权限 API、凭证注入；监测必须能自动停跑，不能只靠模型自称遵守。
3. 昇腾路线团队可跟进 openPangu 训练/RL 仓：评估是否降低从权重到可复现后训练的工程成本，而非仅看榜单。

重点 · 1官方/一手

智谱发布循环架构旗舰 GLM-5.4

  • 11 月 23 日发布：在 GLM-5 基座上取 28 层权重共享、循环执行两次，通过继续训练改造而成，而非从头预训练；规模约 750B，支持视频、图像、文本、文件输入，上下文 100 万 token。
  • 为控制成本，第二次循环复用第一次的稀疏注意力索引，额外 KV 缓存只多一个滑动窗口。
  • 在同架构 30B 模型上做等参数对照：总训练算力约多 10%，数学、科学推理、长上下文提升最明显，GPQA-Diamond 等测试的平均输出长度缩短 10–14%，部分推理从写出的思维链转入循环深度。
  • 目前向 GLM Coding Plan 全量用户、ZCode 与 Z.ai Chat 开放；API 待安全评估后开放，权重在安全加固后开源。官方承认模型容易陷入过长思考，并称更大的下一代模型“很快就绪”。
为什么重要

继上周 Thinking Machines 之后，又一家实验室把循环层用在旗舰模型上；思维链变短，依赖读思维链的安全监控会更难做。【分析】

疑点

公开数字全部来自 30B 对照实验，“2–3T 级”尚无第三方评测支撑。

来源智谱 · 智谱开放平台文档 · The Decoder

重点 · 2官方/一手

Anthropic 推出 Claude Ship，可自动审批合并请求

  • 11 月 23 日发布 Beta，面向 GitHub 上的 Team 与 Enterprise 客户，由三部分组成：已正式上线的 Code Review；负责修复 CI 失败、合并冲突和评审意见的 PR Steward（设计上不批准、不合并）；按仓库内策略文件决定是否批准的 Claude Approvals。
  • 官方称在 Claude Code 团队内部，6 月到 9 月合并的请求数增加一倍多，被回滚的比例下降 40% 以上；建议先用只观察模式。
  • 文档提示：若开启自动合并且策略不要求人工批准，改动可能无人经手直接合并；启用零数据保留、HIPAA 配置或客户自管密钥的组织暂不可用。
为什么重要

审批是软件流程里最后一道人工关口，现在交给可配置的模型判断，责任划分和审计会成为新问题。【分析】

来源Anthropic · Claude Code 文档 · TechCrunch

重点 · 3官方/一手

微软 MAI 披露 3T 参数基座的强化学习后训练

  • 11 月 23 日，微软 MAI 介绍自研强化学习框架 Rocket：目标是从基座模型直接靠强化学习“爬升”能力，单次训练在数千块 GPU 上持续数周到数月，而不是后训练末尾的短暂阶段。
  • 3T 参数的 MAI Base 2 正在用 Rocket 后训练，官方强调不从第三方模型蒸馏，与 MAI Code 2 系列无关；为提速，对占参数 95% 以上的专家权重和全局注意力 KV 缓存使用 MXFP8 存储。
  • 官方称其模型在内部聚合推理基准上已超过 Claude Opus 4.8，预计几周内超过 GPT-5.6 Sol，曲线尚未见平台期。
为什么重要

微软在 OpenAI 之外自建前沿模型的路线更清楚；对比对象是上一代模型，与当前前沿仍有差距。【分析】

疑点

聚合基准由数十个公开与私有评测合成，构成未公开。

来源微软 MAI

重点 · 4官方/一手

OpenAI 为 ChatGPT 对话推出 GPT-6.2

  • 11 月 23 日起向 Plus、Pro、Business、Enterprise 用户全球推送针对对话调优的 GPT-6.2 Sol；Work 与 Codex 中的模型不变。
  • 系统卡称，该模型在网络安全上达到准备框架的“关键”阈值，生物与化学达到“高”阈值，“AI 自我改进”也达到“高”阈值；部署时沿用 GPT-6.2 Astra 与 Sol 的生物、网络、对齐与反蒸馏防护。
  • 据 The Decoder 转述，内部测试中图像理解从 47.4% 升到 71.7%，困难指令遵循从 62.5% 升到 78.1%。
为什么重要

达到自我改进高阈值的模型开始进入面向数亿人的对话产品，防护措施能否跟上值得持续核对。【分析】

来源OpenAI 系统卡 · The Decoder
